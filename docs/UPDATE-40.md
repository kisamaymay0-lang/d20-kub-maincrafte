# Обновление 40: наборы косметики и напитки в файле

Две вещи, которые раньше были зашиты в код, теперь настраиваются файлами: **кейсы
косметики** и **рецепты напитков**. И одна убрана — лишняя папка.

---

## 1. `content/cosmetics/` больше нет

Косметика полностью описывается одним файлом `settings/cosmetics.yml`. Дополнительные
файлы в `content/cosmetics/` (и `example.yml` из комплекта) убраны: держать две правды
про одну вещь было неудобно — половина записей жила в одном месте, половина в другом.

- Если папка `content/cosmetics/` осталась с прошлой версии — она просто больше не
  читается, файлы можно удалить или перенести записи в `settings/cosmetics.yml`.
- Ничего из уже выданного у игроков не пропадает: id косметики те же.
- `/f8 config` показывает раскладку заново: `content/prefixpacks` и `content/cosmeticpacks`.

---

## 2. Наборы косметики (кейсы) — `content/cosmeticpacks/*.yml`

Устроено ровно как паки префиксов:

| | паки префиксов | наборы косметики |
|---|---|---|
| папка | `content/prefixpacks/` | `content/cosmeticpacks/` |
| ключ списка | `prefixes:` | `cosmetics:` |
| что внутри | файлы из `settings/prefixes.yml` | файлы из `settings/cosmetics.yml` |
| меню | профиль → «Настроить» → префиксы | косметика → «Наборы косметики» |
| команда выдачи | `/profile case pack …` | `/profile case cpack …` |

### Файл набора

```yaml
name: 'Набор косметики №1'      # название на сундучке
time-hours: -1                  # срок кейса в часах с момента выдачи; -1 — бессрочный
cosmetics:                      # файлы моделей из settings/cosmetics.yml
  - kosmetika1                  # имя и цвет возьмутся из settings/cosmetics.yml
  - file: kosmetika2            # тот же вид, но полем
  - file: kosmetika3            # имя и цвет можно переопределить на месте
    name: 'Своё имя'
    color: '#7FF0D2'
```

- Имя файла набора = id пака: `kosmetika-nabor1.yml` → `kosmetika-nabor1`.
- В комплекте лежит `kosmetika-nabor1.yml`: все три модели косметики, кейс бессрочный.
  Он создаётся при первом запуске, дальше живёт сам — правьте или уберите.
- Модель, которой нет в `settings/cosmetics.yml`, набор заводит сам
  (id вида `letniy_kosmetika9`), а в журнал пишет предупреждение: такую косметику
  лучше добавить в настройки, чтобы у неё был нормальный номер и имя.
- `time-hours` — это срок **кейса**, а не выбитой косметики. Кейс сгорел — открыть
  нельзя; выпавшая косметика остаётся навсегда.

### В игре

- `/profile` → «Настроить косметику» → кнопка **«Наборы косметики»** (11-й слот)
  открывает список сундучков-наборов; кнопка «Кейс косметики» (13-й слот) осталась —
  это обычный кейс из всей косметики.
- Сундучок показывает: сколько кейсов набора у игрока, что внутри, когда сгорит
  ближайший. Нажали — видно содержимое; средняя кнопка крутит кейс.
- Вскрытие — та же анимация, что у кейсов префиксов: девять карточек, «поломки»,
  пауза 4 секунды на выигрыш. Выпадает только то, чего у игрока ещё нет.
- Косметику из набора можно надеть прямо в меню набора (как в списке косметики),
  shift + клик — снять.

### Команды администратора

```
/profile case cpack give <ник> <набор> [число]
/profile case cpack take <ник> <набор> [число]
/profile case cpack list <ник>
```

`cpack` можно писать и целиком — `cosmeticpack`. Набор указывается по имени файла
или по строке `name`. Срок кейса начинается с момента выдачи.

## 3. Напитки — `settings/recipe-poilo.yml`

Раньше рецепты, названия, цвета, модели и описания напитков были зашиты в `Shaker.java`.
Теперь всё это — файл `settings/recipe-poilo.yml`. Новый напиток = новый блок в YAML +
`/f8 reload`. Код трогать не нужно.

### Запись напитка

```yaml
recipes:
  kompot:
    name: 'Компот'                     # название в подсказке (золотое)
    color: '#C2412F'                   # цвет жидкости в бутылочке
    model: ''                          # модель: f8resurs:<model>; пусто — только цвет
    description: 'Ягодный компот, как в детстве.'
    hint:                              # необязательно: жёлтая приписка «может стоит добавить…»
      before: 'может стоит добавить в него '
      drink: 'лёд'                     # это слово рисуется подчёркнутым
      after: '?...'
    method: shaker                     # shaker — шейкер, barrel — бочка
    ingredients: [sweet_berries, water_bottle, sugar]
    additives: [ice, honey_bottle]     # только положительные
```

- **`method: shaker`** — напиток смешивается в шейкере из `ingredients`.
  Порядок рецептов в файле = порядок проверки: если набор подходит под два напитка,
  побеждает верхний.
- **`method: barrel`** — напиток не смешивается в шейкере: он настаивается в бамбуковой
  бочке (сейчас так живёт пиратский ром).
- **`additives`** — только положительные добавки. Списка отрицательных нет: всё, чего
  в нём нет, считается плохим (1 — тошнота, 2 — тошнота II + отравление,
  3 и больше — тошнота II + отравление II).
- **`hint`** — по его наличию выбирается маркер описания: есть приписка — ▶, нет — •.
- **`murk`** (муть) — запасной напиток: он выдаётся, когда рецепт не совпал.
  У него пустые `ingredients`, и убирать его из файла не надо.
- Ошибка в файле не ломает напитки: остаются прежние, а причина — в журнале сервера.
  В сообщении об ошибке сразу перечислены допустимые имена ингредиентов.

### Ингредиенты (как их писать)

| в файле | что это |
|---|---|
| `honeycomb` | медовые соты |
| `honey_bottle` | бутылочка мёда |
| `water_bottle` | бутылочка воды |
| `hot_water_bottle` | бутылочка горячей воды |
| `sugar` | сахар |
| `sweet_berries` | сладкие ягоды |
| `ice` | любой лёд |
| `cocoa_beans` | какао-бобы |
| `milk_bucket` | ведро молока |
| `green_dye` | зелёный краситель |

Регистр и дефисы не важны: `Hot-Water-Bottle` = `hot_water_bottle`.

### Что уже в файле

| id | название | рецепт | положительные добавки |
|---|---|---|---|
| `mead` | Медовуха? | соты + горячая вода | сахар |
| `matcha_tea` | Матча-чай | зелёный краситель + горячая вода | мёд, молоко, лёд |
| `daiquiri` | Дайкири? | сладкие ягоды + сахар + вода | лёд, ягоды |
| `iced_latte` | Айс-Латте | какао-бобы + лёд + молоко | мёд, лёд |
| `murk` | Муть | — (запасной) | — |
| `pirate_rum` | Пиратский ром | только бочка | — |

Названия, цвета, модели и описания этих напитков в файле **точно те же**, что были в
коде: в игре ничего не поменялось, просто теперь это можно править.

### Новый напиток в руках

`/f8` → «Предметы» → «Напитки» показывает комплект и **всё, что дописано в файл**:
новый напиток появляется в меню сам, его можно взять и попробовать без ожидания
пересборки. Пиратский ром по-прежнему берётся из бочки — он `method: barrel`.

## 4. Команды и файлы — короткая шпаргалка

```
/f8 reload                       перечитать всё: напитки, косметику, паки
/profile case cpack …            кейсы наборов косметики
/profile case pack …             кейсы паков префиксов
/profile cosmetic reload         перечитать косметику и наборы
/profile prefix reload           перечитать префиксы и паки
```

| файл | что настраивает |
|---|---|
| `settings/cosmetics.yml` | вся косметика: id, имя, цвет, модель |
| `settings/recipe-poilo.yml` | все напитки: рецепт, вид, описание, добавки |
| `content/cosmeticpacks/*.yml` | наборы косметики (кейсы) |
| `content/prefixpacks/*.yml` | паки префиксов (кейсы) |
