# Обновление 39 — Воск в названии и ступень из решётки

Цифра в названии плагина больше не меняется: версия остаётся **10.39**.

## 1. Вощёный блок ломается вощёным и так и называется

Название предмета теперь зависит не только от ступени, но и от воска:

| Ступень | Без воска | С воском |
|---|---|---|
| `1s` | Медный нотный блок | Вощёный медный нотный блок |
| `2s` | Потемневший медный нотный блок | Вощёный потемневший медный нотный блок |
| `3s` | Состаренный медный нотный блок | Вощёный состаренный медный нотный блок |
| `4s` | Окисленный медный нотный блок | Вощёный окисленный медный нотный блок |

- Воск уже ехал в предмете (`adaptation:copper_waxed`) — теперь он виден и в названии:
  `CopperNoteStages.itemName(stage, waxed)`.
- Скобок и лишних строк лора по-прежнему нет: одна подсказка «Поставьте и нажмите
  ПКМ, чтобы настроить ноты».
- Вощёный предмет ставится вощёным: окисление стоит, топор снимает сначала воск
  (`WAX_OFF`), потом ступень (`SCRAPE`) — как в ванили.

## 2. Из какой решётки крафтят — такой блок и получают

Крафт остался бесформенным (нотный блок + редстоун + алмаз + любая медная решётка),
но результат теперь зависит от решётки:

| Решётка в сетке | Что получится |
|---|---|
| `copper_grate` | `1s`, без воска |
| `exposed_copper_grate` | `2s`, без воска |
| `weathered_copper_grate` | `3s`, без воска |
| `oxidized_copper_grate` | `4s`, без воска |
| `waxed_copper_grate` | `1s` + воск |
| `waxed_exposed_copper_grate` | `2s` + воск |
| `waxed_weathered_copper_grate` | `3s` + воск |
| `waxed_oxidized_copper_grate` | `4s` + воск |

Как это сделано: рецепт один, а результат подменяется в `PrepareItemCraftEvent` —
предпросмотр в сетке и выданный предмет сразу правильной ступени. Свою сетку узнаём
по составу (`hasRecipeSingles` + `grateInMatrix`), а не по ключу рецепта, чтобы не
зависеть от API.

## 3. Тесты

- `CopperNoteStagesTest.waxedNamesSayTheyAreWaxed` — все четыре вощёных названия,
  неизменность названий без воска, устойчивость к мусорному номеру ступени.
- `CopperBlockRecipeTest.craftedStageFollowsTheGrate` — ступень и воск для всех
  восьми решёток, посторонний материал даёт `1s` без воска.

## 5. Ноты не теряются при окислении

Раньше смена ступени по времени снимала старый блок и ставила новый, и на один-два
тика место оказывалось пустым. Проверка питания в `tickRedstone()` видела пустое
место, вычёркивала блок из «играющих», и он замолкал — ноты приходилось расставлять
заново, хотя они никуда не делись из `blocks.yml`.

- Блок больше не вычёркивается сразу: место может быть пустым до 40 тиков
  (`POWER_MISS_GRACE_TICKS`), и ноты в это время ждут.
- После установки новой ступени `restoreTrigger()` возвращает блок в список
  играющих с текущим состоянием сигнала — без лишнего срабатывания.
- Поломка блока, поршень и выключение сервера по-прежнему чистят все карты сразу.

## 6. Медные блоки играют трубой

С 26.1 у медных блоков свой инструмент нотного блока — труба, своя на каждую
ступень окисления. Раньше проверка искала только `COPPER`-материал общего вида,
поэтому ступени и формы меди узнавались как обычный камень.

- `instrumentKey(material)` заменил старую таблицу и возвращает ключ звука:
  `block.note_block.trumpet`, `trumpet_exposed`, `trumpet_weathered`,
  `trumpet_oxidized`.
- Труба — для всех медных **блоков**: блок, резная, гранёная, решётка, лампа,
  ступени, плиты, сундук, вощёные варианты. Руды, слитки, самородки и молниеотвод
  остаются при прежнем инструменте.
- Заодно проверены остальные группы ванили: кости → ксилофон, золото → колокол,
  глина → флейта, лёд и аметист → перезвон, шерсть → гитара, железо → железный
  ксилофон, душа → коровий колокол, тыква → диджериду, изумруд → бит, сено →
  банджо, светокамень → плин, дерево → бас, стекло → хэт, песок/гравий/порошок
  бетона → снейр, камень/руды/кирпич → бас-барабан, головы → их собственные звуки.
- Ключ звука превращается в `Sound` через реестр: если сервер такого звука не знает,
  играет арфа, а не тишина.

## 7. Из шейкера можно налить в рюмку RP Engine

Рюмка — это piece из RP Engine (предмет с блоком `place:`). ПКМ по поставленной
рюмке, когда в шейкере есть готовый напиток:

1. рюмка исчезает;
2. на её месте появляется бутылочка с этим напитком;
3. напиток уходит из шейкера (стекло не возвращается).

Что для этого есть в плагине:

- `ShotGlass` слушает `PlayerInteractAtEntityEvent` — то же событие, из которого
  RP Engine сам рассылает `ModelInteractEvent`, но на `LOWEST`: так налив не
  зависит от внутренних обработчиков движка, а отмена клика не даёт рюмке
  сработать повторно.
- Модель ищется через публичные интерфейсы `Models.at(hitbox)` и `Placement`.
  Классы берутся по имени, поэтому без установленного RP Engine плагин работает
  как раньше, а в консоль пишется «RP Engine не найден».
- Методы вызываются через интерфейс, а не через класс объекта: реализация
  `Placement` внутри RP Engine — приватный класс, и вызов через
  `getClass().getMethod(...)` падал с `IllegalAccessException` (на этом стояла
  первая версия — клик был, а рюмка не убиралась).
- Клик не перехватывается, если наливать нечего: нет шейкера в руках, в нём нет
  готового напитка или RP Engine отказался убирать рюмку.
- Список id рюмок — `shaker.glass-models` в `config.yml`, формат «папка:предмет»,
  по умолчанию `testpack:statue`.
- Готовый файл рюмки, сверенный с FORMAT.md RP Engine, лежит в
  [`docs/rpengine/shot-glass.yml`](rpengine/shot-glass.yml). В нём нет `place.type`
  и нет папок `models/`/`furniture/` — таких в RP Engine не существует; модель
  ставится через `model:` + `place:`.
