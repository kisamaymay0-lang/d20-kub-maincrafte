# f8-plugin 9.2 — поведение печки, плавное небо и оптимизация

**Paper 1.21.11 / Java 21.** Продолжение 9.1. Файлы созвездий, связи,
награды, рецепты, чары, предметы и прогресс сохраняются.

## Установка

Остановите свой сервер и замените старый JAR на `target/adaptation-9.2.jar`
из артефакта `f8-plugin-9.2`. Не оставляйте одновременно два JAR плагина.
Папку данных плагина не удаляйте. **Ресурспак от 9.1 подходит без изменений**:
плавное появление работает и со своими текстурами/моделями звёзд.

## Shift + ПКМ как у печки

- Без Shift — меню медного нотного блока.
- Shift и **предмет хотя бы в одной руке** — ванильное размещение/использование
  предмета, без меню.
- Shift и **обе руки пустые** — меню, как у обычной печки.

В 9.1 принудительный `DENY` заставлял Paper возвращаться из `useItemOn` ДО
размещения предмета. Теперь плагин не переопределяет результат такого события:
ваниль сама обрабатывает secondary-use. Отмены сторонних защитных плагинов
не обходятся. Маркер медного блока не перенастраивается пустой рукой.

## Появление, уход и перемещение неба

- Звёзды плавно набирают **масштаб и яркость**, затем плавно угасают и уменьшаются.
  Это не изменение альфа-канала PNG: отдельного opacity у ItemDisplay нет.
- По умолчанию переход занимает 40 тиков (2 секунды при 20 TPS).
  Линии уходят вместе со звёздами; сохранённый прогресс не удаляется.
- Обычные перемещения больше не вызывают массовые мгновенные телепортации на
  каждом `PlayerMoveEvent`. Общая точка неба обновляется раз в 2 тика, клиент
  сглаживает перенос за 3 тика. Небольшой ограниченный прогноз уменьшает
  запаздывание при равномерной ходьбе, не учитывая yaw/pitch камеры.
- К звёздам по-прежнему нельзя подойти: небо следует за XYZ игрока. Прицеливание
  учитывает оценку сглаженной позиции, а не будущую целевую точку телепортации.
- При скачке более 16 блоков старое изображение удаляется, а новое проявляется
  на месте прибытия; нет длинного пролёта неба через мир. При обычном перемещении
  направление по камере не меняется. Высокий пинг/низкий TPS всё ещё могут быть
  заметны: это серверные display-сущности, а не мод клиентского небесного рендера.

```yaml
constellations:
  fade-duration-ticks: 40
  follow-interpolation-ticks: 3
  rotation-update-ticks: 4
  star-rotation-degrees-per-second: 4.0
```

Старый конфиг можно оставить — новые параметры имеют эти значения по умолчанию.
После изменения настроек — `/stars reload`. Вращение по-прежнему 4°/секунду,
но отправляется реже, а промежуточные кадры дорисовывает клиент.

## Сброс выбора

- Промах после выбора звезды: **«Выбор сброшен.»**
- Промах без активного выбора остаётся тихим — сообщения не мешают осмотру руд.
- Выбор сбрасывается, если в **основной руке** больше нет подзорной трубы:
  смена слота, перенос в дополнительную руку, выбрасывание, перемещение в
  инвентаре или замена предмета другим плагином. Для изменений без событий
  есть проверка раз в 2 тика; сообщение приходит только один раз.
- «Звезда выбрана.» и пунктирное превью между любыми созвездиями сохранены.
  Проверка допустимой связи и выдача награды не изменены.

## Что оптимизировано

| Модуль | Изменение | Что намеренно не менялось |
| --- | --- | --- |
| Созвездия | Направления, модели и матрицы постоянных линий кэшируются; поворот рассчитывается один раз на звезду для всех игроков. Нет обхода всех игроков каждые 2 тика, когда неба нет. | Карта неба, звёзды, связи, допуск прицеливания, награды |
| Пакеты звёзд | Повороты по умолчанию 5 раз/сек вместо 10; плавность обеспечивает клиент. XYZ отправляется с фиксированной частотой и только при изменении цели. | Угловая скорость вращения и независимость от камеры |
| Поиск звезды | Одна позиция глаз на поиск, кэшированные смещения и глобальные ключи; без тригонометрии/новой Location для каждой звезды. | Превью не раскрывает принадлежность к созвездию |
| Сохранение | Изменения обновляются в памяти сразу. YAML готовится на главном потоке пакетно, обычно не чаще раза в 20 тиков; запись строк — одним фоновым писателем. Устаревшие снимки одного файла объединяются. | Чтение Bukkit/ItemStack никогда не выполняется в фоне |
| Прогресс | В YAML-структуре обновляется только изменившийся игрок, а не все игроки при каждом луче. Перед выдачей награды ожидается запись, как и раньше. | Однократная награда, сохранение завершений и сбросов |
| Медный блок | Клики одного тика объединяются; неизменённые и пустые GUI не переписываются. Пустые сохранённые окна не опрашиваются на редстоун. При воспроизведении читается один слот, а не весь GUI. | Редстоун проверяется каждый тик; пластинки, частицы, пауза, крафт, запрет поршней |
| Адаптация | Один снимок ItemMeta вместо нескольких; постоянный заголовок боссбара больше не пересобирается 10 раз/сек. | Защита, бонусы, интервалы, уровни и перезарядка |
| Флаконы | Read-only PDC вместо копирования ItemMeta в цикле; убран тяжёлый String.format для времени. | 90 секунд яда, частота частиц/HUD, попадания и эффекты |
| Откат | ArrayDeque вместо узлов LinkedList, без лишнего clone уже новой Location; один дескриптор задачи вместо карты со случайным UUID. | Все игроки отслеживаются каждые 10 тиков, даже без тотема; глубина истории 5 секунд |
| d20, меню, икра | Проверены: нет фоновых записей/полного обхода мира, таймеры d20 конечные и очищаются. Рисковые переписывания не делались. | Броски, шансы, эффекты, рецепты и выдача |

Запись файлов идёт по порядку, через временный файл и атомарную замену
(где она поддерживается файловой системой; иначе используется обычная замена): старый снимок
не может перезаписать новый. При штатном выключении собираются последние изменения
и ожидается завершение очереди. Ошибки диска выводятся в лог. При аварийном завершении
процесса до пакетного сохранения возможна потеря последней секунды обычных изменений;
перед наградой и административным сбросом используется отдельное ожидание записи.
Редкие административные изменения файлов самих созвездий остаются синхронными,
чтобы немедленная перезагрузка читала уже записанный файл.

### Чего эта проверка не доказывает

Это аудит кода и автоматические тесты, **не измерение TPS/MSPT на настоящем сервере**.
Стоимость display-сущностей остаётся пропорциональна числу игроков, звёзд и линий.
Тысячи звёзд на каждого игрока, большие редстоун-схемы, шейдеры и высокий пинг всё ещё
могут давать нагрузку. Частота проверки редстоуна не снижалась, чтобы не терять
короткие импульсы. Если нагрузка заметна, нужен профиль твоего сервера (например spark),
а не обещание «плагин вообще не нагружает».

## Проверки без Minecraft-сервера

```sh
python3 scripts/build_resourcepack.py --check
mvn --batch-mode clean verify
```

Тесты: правило печки для обеих рук, плавный обратимый переход, сглаженное движение,
остановка/телепорт/граница мира/переполнение счётчика тиков, эквивалентность кэшированного
прицеливания, атомарная запись UTF-8, объединение очереди, порядок записей и ошибки диска.
Сохранены все прежние тесты адаптации, редстоуна, геометрии, превью и песен.

### Проверить в игре у владельца сервера

- Shift + ПКМ блоком в основной и дополнительной руке; затем обе руки пустые.
- Ночь → день → ночь: плавный переход, старые связи возвращаются. Пробежать, резко
  остановиться, покрутить камерой, телепортироваться далеко и проверить прицеливание.
- Выбрать звезду и промахнуться; затем промахнуться ещё раз: сообщение только один раз.
  Повторить со сменой слота, F, выбрасыванием и перемещением трубы в инвентаре.
- Изменить содержимое медного блока, закрыть окно, штатно перезапустить сервер:
  предметы сохранены. Проверить поршни, короткие импульсы и пластинку.
- Собрать созвездие, перезапустить сервер: награда повторно не выдаётся.
