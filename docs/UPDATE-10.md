# F8 10.2 — надёжная раздача ресурспака и переделанный кувшин

Paper 1.21.11 / Java 21. Механики кувшина, изморози, профилей и созвездий не
менялись: этот выпуск про доставку ресурспака и внешний вид кувшина.

## Что обновлять

1. **JAR** — заменяется как обычно: `target/f8-plugin-10.2.jar` в `plugins/`.
2. **ZIP ресурспака** — `f8resurs-resourcepack.zip` из релиза. Дело не только в
   кувшине: в пакете исправлен `assets/minecraft/blockstates/note_block.json`.
   Со старым архивом кувшин останется прежним, а часть состояний нот-блока
   (например, нот-блок на медном блоке или с головой моба) может показываться
   «отсутствующей моделью» — фиолетово-чёрной клеткой.

Резервная копия папки `plugins/f8-plugin/` перед заменой JAR не помешает, хотя
форматы данных в 10.2 не менялись.

## Раздача ресурспака: свой HTTP-сервер убран

Раньше плагин поднимал внутри себя HTTP-сервер на порту `resource-pack-port`
и раздавал клиентам встроенную в JAR копию архива. Это убрано полностью
(нет ни сервера, ни копии в JAR, ни ключа `resource-pack-port`).

Теперь пак отдаёт **сам Minecraft**: клиент скачивает файл по обычной ссылке,
как любой серверный ресурспак. Плагин перед входом игрока предлагает загрузку
через `addResourcePack`, поэтому игрокам ничего класть вручную не нужно.

Настройка в `plugins/f8-plugin/config.yml`:

```
resource-pack:
  url: 'https://github.com/kisamaymay0-lang/d20-kub-maincrafte/releases/latest/download/f8resurs-resourcepack.zip'
  prompt: 'Ресурспак F8: кувшины, изморозь и предметы'
```

* `url` — адрес ZIP-файла (не страницы просмотра). Пустая строка выключает
  раздачу: игроки ставят пак из релиза вручную.
* `prompt` — текст предложения. Пустая строка убирает текст.

Ссылка из примера работает сама после того, как появится релиз с ZIP — на это
настроен CI:

```
git tag v10.2
git push origin v10.2
```

CI соберёт JAR, проверит пакет, создаст релиз `v10.2` и приложит к нему
`f8-plugin-10.2.jar` и `f8resurs-resourcepack.zip`. Ссылка `releases/latest/download/...`
всегда указывает на последний релиз, поэтому после следующих выпусков в
`config.yml` ничего менять не нужно.

**Проверка ссылки перед запуском.** Откройте её в браузере в режиме инкогнито:
должно начаться скачивание файла. Если открывается страница (обзор диска,
Google Drive «предпросмотр», Dropbox и т. п.) — клиент получит HTML вместо ZIP
и пак не применится.

**Поведение при проблемах со ссылкой.** Плагин скачивает файл сам при запуске
сервера, считает SHA-1 и только после этого предлагает пак игрокам. Если ссылка
недоступна (404, нет интернета, таймаут), сервер работает как обычно: пак просто
не предлагается, а попытки повторяются в фоне каждые 5 минут. В логе будет одна
понятная строка, а не поток ошибок на каждый вход:

```
[WARN] Не удалось получить ресурспак по ссылке ...: ...
[WARN] Игроки смогут поставить пак вручную: f8resurs-resourcepack.zip из релиза -> .minecraft/resourcepacks.
```

Требовать пак обязательно нельзя: `require-resource-pack` в `server.properties`
лучше оставить `false`, иначе игрок без пака просто не зайдёт. Причины
предпочесть раздачу самим Minecraft: свой сервер внутри плагина зависел от
открытого порта на хостинге и ломался там, где этот порт закрыт, а клиенты
неохотно принимают паки с «серых» адресов.

## Кувшин

Механика прежняя: рыбалка в пустыне, установка блоком, выливание до 9 бутылочек,
компаратор 1–9, питьё 1.6 с, нагрудник, замедление/прыжок/элитры, защита
блокстейта. Изменился только вид — и он больше не «куб с бруском сверху».

* Текстура. Лист `block/gor4ok.png` (40×40) собирается скриптом
  `scripts/build_jug_texture.py` **из присланного рисунка**
  `scripts/jug_texture_source.png`: исходные пиксели переносятся без изменений,
  доливаются только связные тона из той же палитры (светлая глина для горла,
  тёмная для дна, тёмный зев, золотая жидкость). Ваши полосы и терракота
  по-прежнему в основе кувшина.
* Модель. Тулово — ступени с непрерывными полосами (полосы не «ломаются» на
  срезах), светлое горло, венчик сделан **кольцом**, поэтому у пустого кувшина
  видно тёмный зев, а у наполненного — жидкость. Добавлены ручки-ушки.
* Предмет. Пустой и наполненный кувшин используют те же 3D-модели (в инвентаре,
  в руке, на земле и в рамке), отдельных «плоских» иконок больше нет — раньше
  наполненный предмет брал несуществующую текстуру и показывался фиолетовым.
* Нот-блок. Правила `note_block.json` теперь покрывают все 575 сочетаний
  `note` × `instrument` ровно один раз; состояния с головой моба или на медном
  блоке больше не остаются без модели.

Посмотреть, как выглядит кувшин, можно без Minecraft:

```
python3 scripts/build_jug_texture.py   # собрать лист текстур
python3 scripts/build_jug_models.py    # собрать модели
python3 scripts/preview_models.py      # картинки в artifacts/preview/
python3 scripts/test_jug.py            # 10 проверок: UV, состояния блока, текстура, раздача
```

## Если кувшин всё ещё «не тот»

1. Убедитесь, что клиент взял новый пак: при входе должно появиться предложение
   загрузки, а SHA-1 в логе сервера — совпадать с `sha1sum f8resurs-resourcepack.zip`.
2. После обновления нажмите `F3 + T` (или перезайдите), чтобы клиент перечитал
   текстуры: старый пак кэшируется по SHA-1.
3. Сторонний ресурспак с более высоким приоритетом не должен переопределять
   `assets/minecraft/blockstates/note_block.json` и `assets/f8resurs/**`.
4. Кувшин стоит там, где под нот-блоком нет блока, который меняет инструмент
   (например, шерсть или сено): плагин защищает блокстейт, но первое состояние
   задаётся при установке — если поставить кувшин на сено, возможен кадр с
   чужой моделью до отката.
