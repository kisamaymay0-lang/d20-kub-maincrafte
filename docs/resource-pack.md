# Как игрокам получить ресурспак

Коротко: **раздавать нужно не `f8resurspack-fixed.zip`, а пак, который собирает
CraftEngine.** Отдельный zip — это только половина: в нём лежат модели и
текстуры f8resurs, но нет того, что CraftEngine добавляет при генерации.

## Почему отдельный zip не работает

Кувшин и медный нотный блок — кастомные блоки CraftEngine. Клиент рисует их не
по id блока (своего id у него в ванили нет), а по блок-стейту состояния-носителя:
CraftEngine берёт свободное состояние из группы `auto_state` и **генерирует**
привязку «это состояние → модель `f8resurs:block/…`». Этих привязок, атласов и
определений предметов в `f8resurspack-fixed.zip` нет и быть не может — они
появляются только в собранном паке.

Поэтому у игрока с одним только `f8resurspack-fixed.zip`:

* кувшин на земле выглядит как ножка гриба (носитель `mushroom_stem`),
* медный нотный блок — как обычный сплошной блок (носитель из группы `solid`),
* а если пак ещё и не применился — не отображается вообще ничего.

Второе стоит проверить отдельно: в `pack.mcmeta` пака f8resurs написано

```json
"pack_format": 75,
"min_format": 34,
"max_format": 75
```

Начиная с 1.21.9 клиент требует `min_format`/`max_format` и помечает пак как
«несовместимый», если его формат выше `max_format`. Формат своего клиента игрок
видит командой `/version` или хоткеем `F3`+`V` — если число больше 75, пак не
загрузится вовсе, и это выглядит ровно как «текстуры не отобразились».
(Точное число формата для конкретной версии здесь проверить не удалось —
метаданные Mojang из песочницы недоступны; сверьте `/version` у игрока.)

У пака, который собирает CraftEngine, диапазон берётся из его конфига
(`resource-pack.supported-version: min: server, max: latest`) и под текущую
версию сервера подходит всегда.

## Как раздавать правильно

Всё настраивается в `plugins/CraftEngine/config.yml`, раздел `resource-pack`.

### 1. Ваш пак уже внутри CraftEngine

Вы положили ресурспак в `plugins/CraftEngine/resources/<ваш пак>/resourcepack/` —
значит он уже участвует в генерации, ничего добавлять не нужно. Если удобнее
держать его отдельным zip, CraftEngine умеет подмешивать чужие паки:

```yaml
resource-pack:
  merge-external-zip-files:
    - "f8-plugin/f8resurspack-fixed.zip"   # путь от plugins/
```

Конфликты файлов он разруливает сам (`duplicated-files-handler`: слияние
`pack.mcmeta`, атласов, `items/*.json`, legacy-моделей).

### 2. CraftEngine сам отдаёт пак игрокам

```yaml
resource-pack:
  self-host:
    ip: "auto"
    port: "auto"
    protocol: "http"
  delivery:
    prompt: "<yellow>Примите ресурспак, без него кувшины и медные блоки выглядят неправильно.</yellow>"
    send-on-join: true
    kick-if-declined: false        # true — кикать тех, кто отклонил
    kick-if-failed-to-apply: false
    strict-player-uuid-validation: true   # на офлайн-сервере поставить false
```

`self-host` поднимает HTTP-сервер прямо в CraftEngine; `port: "auto"` подбирает
свободный порт. Если порт наружу не торчит, нужен внешний хостинг — см. вики:
<https://xiao-momi.github.io/craft-engine-wiki/getting_start/set_up_host/>.

`strict-player-uuid-validation: true` требует подтверждённый UUID для скачивания
— на сервере в офлайн-режиме из-за этого пак не скачается, ставьте `false`.

### 3. Пересобрать и разослать

```text
/ce reload          # или /ce workflow default
```

Воркфлоу по умолчанию (`trigger: reload_pack`) делает `generate → validate → zip
→ upload → send_pack`, то есть пересобирает пак и рассылает его всем онлайн.

Готовый файл лежит в `plugins/CraftEngine/generated/resource_pack.zip`, копия для
раздачи — в `plugins/CraftEngine/cache/hosted/default/resource_pack.zip`.

## Если ваш пак уже подключён в server.properties

Так и было задумано, когда плагин перестал раздавать пак сам (10.2): «ресурспак —
не дело плагина, у владельца свой пак, он подключён в `server.properties`».
Ничего ломать не нужно — но важно понимать, что это **два разных пака**:

* пак из `server.properties` — ваш f8resurs: префиксы, медали, еда, модели;
* пак CraftEngine — то, что он генерирует: привязки состояний-носителей к
  моделям кувшина и медного блока, атласы, определения предметов.

Клиент 1.20.3+ принимает несколько паков сразу, так что оба применяются
параллельно. Если у игрока «не загрузился ресурспак с CraftEngine», а ваш
загрузился — значит, не скачался именно второй: почти всегда это недостижимый
`self-host` (порт не открыт наружу) или `strict-player-uuid-validation: true` на
офлайн-сервере. Симптом ровно такой: иконки и еда на месте, а кувшин — ножка
гриба. Подмена вашего zip вместо пака CraftEngine это не лечит: в вашем zip
сгенерированных привязок нет.

Проверить, доходит ли пак: в логе сервера CraftEngine пишет отправку пака, а
игрок видит предложение принять его при входе. Если предложения нет — смотрите
`delivery.send-on-join` и доступность порта из `self-host`.

## Если раздаёте через server.properties

Возможно, но файл должен быть **собранный CraftEngine**, а не
`f8resurspack-fixed.zip`:

```properties
resource-pack=https://ваш-хост/resource_pack.zip
resource-pack-sha1=<sha1 этого файла>
resource-pack-prompt=§eПримите ресурспак
require-resource-pack=true
```

`sha1` обязан совпадать с файлом побайтово, иначе клиент молча откажется его
применять — это вторая частая причина «текстуры не отобразились».

## Если игрок ставит пак вручную

Файл кладётся в `.minecraft/resourcepacks/` и включается в настройках. Так
тоже нужен собранный CraftEngine пак. И учтите: такой пак не обновится сам,
когда вы пересоберёте блоки.

## Проверка

* В логе CraftEngine при старте/`/ce reload` нет ошибок валидации пака
  (воркфлоу содержит шаг `validate` — он ловит отсутствующие текстуры и модели).
* У игрока: `/version` или `F3`+`V` — формат клиента; кувшин в мире рисуется
  кувшином, а не ножкой гриба.
* Плагин при этом ни при чём: он ставит блоки и не раздаёт пак (свою раздачу
  плагин перестал делать ещё в 10.2).
